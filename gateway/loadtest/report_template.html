pybox-gateway 부하 테스트 타임라인

언제 몇 개의 에이전트가 통신 중이었나

에이전트가 게이트웨이에 열어 둔 요청 수(클라이언트 측, 0.5초 간격). 점선은 전체 합계.

게이트웨이 내부: 업스트림 슬롯 사용과 대기열

프로바이더별 업스트림 동시 실행 상한은 –. 실선은 실제로 업스트림에 나가 있는 요청, 점선은 슬롯을 기다리는 요청.

요청 하나하나의 타임라인

한 줄이 에이전트 하나, 막대 하나가 요청 하나. 옅은 부분은 첫 바이트 전(게이트웨이 대기 + 업스트림 처리), 진한 부분은 스트리밍 수신. 빨간 막대는 실패.

지연 시간 변화: 첫 바이트까지 (TTFB)

요청 시작 시각 기준 10초 구간별 중앙값(실선)과 p95(점선). 스트리밍 요청만.

게이트웨이 큐 대기 시간

응답 헤더 x-gateway-queue-ms로 측정한, 요청이 업스트림 슬롯을 기다린 시간. 10초 구간별 p95.

지연 시간 변화: 전체 응답 완료

요청 시작부터 스트림 끝까지. 10초 구간별 중앙값.

게이트웨이 CPU 사용률

게이트웨이 프로세스의 CPU 사용률, 0.5초 간격 (100% = 코어 1개, 측정 머신 4코어).

게이트웨이 메모리 (RSS)

게이트웨이 TCP 소켓

들어오는 연결(에이전트 → 게이트웨이)과 나가는 연결(게이트웨이 → 프로바이더, 커넥션 풀). 나가는 연결이 적게 유지되는 것이 풀링/HTTP2 효과.

게이트웨이를 지나간 트래픽

에이전트 쪽에서 본 초당 바이트, 2초 구간. 업로드는 요청 본문(프롬프트), 다운로드는 응답 스트림을 수신 구간에 고르게 나눠 계산. 같은 바이트가 프로바이더 쪽으로도 한 번 더 오갑니다.
